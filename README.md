# 角色动画制作台

React 负责编辑、画布和播放；Python 负责动画计算、工程校验、JSON 存储与动作导出。

## 功能

- 内置简单人形骨架，通过父子层级做前向运动学求值。
- 任意时间拖动预览，姿态按时间线性插值，角度使用 ±180° 最短路径跨越 0°/360°。
- 关键姿态支持跳转、移动时间、复制和撤销。
- 支持动作分层：每层拥有独立关键帧、作用骨骼、权重、时间范围与淡入淡出；层在局部姿态空间按权重覆盖所选骨骼后再做父子旋转求值，未选父骨骼含义保持明确（层只改所选骨骼的局部变换，子骨骼继续随父级世界旋转累积）。
- 层关键帧可单独选择、移动和编辑；时间窗边界配合淡入淡出保证叠加/切换动作不跳姿，保存重开后逐帧预览与导出共用同一求值结果。
- 支持把多层动作按时间范围 + 骨骼范围「整理」成可继续编辑的新动作：按 60fps 逐帧烘焙合成姿态（含平滑权重过渡，逐帧精确固化），整理片段播放与原工程一致，范围以外内容和源分层工程均不改动；整理前会报告缺失骨骼和部分覆盖的不兼容层，任一问题都直接放弃，不会提交半份结果；整理后在原动作与新动作之间逐帧核对姿态，失败时完整保留分层工程。
- 动作层支持权重关键帧，可在淡入淡出过程中任意时刻平滑过渡，并支持过渡中途正/反向反复调整；带权重关键帧的层可直接整理。
- 整理后的局部返修：源工程修改后，自动列出旧整理动作中受影响的时间区间与骨骼，由用户勾选要更新的区间；含人工返修关键帧的区间单独提示，可保留手工结果或重新采用源动作，不会静默覆盖；相邻返修区间保持姿态连续，每次应用是独立一步，撤销一处决定不影响其他已确认区间。
- 同一段源动作可被多个整理动作共享引用：源更新后动作库面板列出每个受影响动作的区间数（并标注共享同一源片段），逐动作分别查看受影响时间、骨骼与采用依据（相交的已确认决定及其源版本）后独立决定，绝不因源相同而强制同步。
- 多个动作共享同一源修订时可放入**同一批次审阅**：批次为每个受影响动作建立各自独立的草稿（两个共享源动作即两份草稿），在同一界面逐项选择「采用新源 / 保留旧依据 / 继续待定」；提交批次只发布所有区间都已明确决定的动作，未决定动作的区间与采用依据随工程保存，保存重开后仍能继续本批。源再次修订后重开本批，新出现的冲突区间以待定加入并保留旧决定的依据。
- 批次内未发布的决定可整项取消：对应动作的草稿恢复原状并移除该批次的决定记录，其他批次（或直接返修）已发布的动作修订与决定不受影响。
- 一次源修订的采用决定可保存为多个可比较的方案：每个方案从当前动作复制、独立确认「采用源 / 保留手工」决定；保留的手工关键帧以 `origin_source_version` 明确依附于确认时的源版本，后续再改源仍能识别冲突。方案对比表同时展示原分层动作（当前源版本）、当前动作、旧修订与各方案在同一时刻的逐骨骼姿态，高亮与源的差异（差异即来自人工采用/保留）；并对每个方案给出更新区间内 / 边界 / 区间外的最大相邻帧姿态差，核对含平滑权重过渡与相邻局部更新的边界连续性。
- 发布方案只把该方案固化为动作新修订（旧发布版本仍在「回放修订」中可播放），其余方案保持草稿可继续编辑；已发布方案只读。
- 每条采用决定进入决定日志（时间区间、骨骼、source/keep、依据的源版本、所属方案）：两次修订影响相交时，分析结果会列出后一次依赖的已确认决定；撤回较早决定前先展示依赖它的后续决定与仍可独立保留的较晚结果，确认后仅恢复该决定自身区间，较晚的无关返修保持不动。
- 共享关系、采用方案、决定日志与独立撤回范围全部随工程保存，关闭重开后不变。
- 整理动作带修订号（revision）与历史版本快照：保存重开后仍能区分源修订、整理结果与人工返修（关键帧 origin 标记），旧版本可在动作面板单独回放。
- 源工程（`version`）与每个整理动作（`source` 溯源：来源动作 id、源版本、时间/骨骼范围、fps、生成时间）分开保存；撤销整理、修改底层关键帧后重新整理、保存重开都能区分源动作与新动作的版本。
- 播放支持重复循环与单次播放。
- 保存前检查缺失父骨骼、重复根节点、自引用、层级循环、缺失骨骼姿态和时间越界等冲突。
- Python 工程原子写入 `backend/data/project.json`。
- 导出按固定 FPS 生成每帧的局部姿态和世界姿态，前端保存时会与 Python 导出结果比对。

## 启动

```bash
cd backend
python server.py --reset --port 8000
```

```bash
cd frontend
npm install
npm run dev
```

打开 Vite 输出的本地地址（默认 `http://127.0.0.1:5173`）。Vite 已把 `/api` 代理到 Python 服务。

## 测试与构建

```bash
cd backend
python -m unittest discover -s tests -v
python -m py_compile server.py animation_core.py

cd ../frontend
npm test
npm run build
```

## HTTP API

- `GET /api/project`：读取工程，不存在时初始化内置角色。
- `POST /api/project`：校验并保存工程。
- `GET /api/evaluate?time=0.63`：获取指定时刻的局部姿态和世界姿态。
- `GET /api/export?fps=24`：导出逐帧动作数据。
- `POST /api/bake`：按 `{project, range_start, range_end, bones, name}` 原子整理新动作；存在缺失骨骼或不兼容内容时返回错误且不修改工程。
- `POST /api/rebake`：按 `{project, action_id}` 返回受影响区间分析（含采用依据）；附带 `decisions`（每区间 `source`/`keep`）时应用局部返修并返回带新修订号与历史快照的动作；附 `variant_id` 时决定写入该草稿方案而非当前动作。
- `POST /api/variants`：`{project, action_id, op: "create"|"publish", variant_id?, name?}` 新建采用方案或把草稿方案发布为动作新修订。
- `POST /api/withdraw`：`{project, action_id, decision_id}` 返回撤回影响分析（依赖决定与可独立保留结果）；附 `confirm: true` 时撤回该决定并只恢复其自身区间。
- `POST /api/review-batch`：源修订批次审阅。
  - `op: "create"`（可附 `action_ids`/`batch_id`/`name`）：为所有受影响动作各建一份批次草稿，返回 `{project, batch}`。
  - `op: "get"`（`batch_id`）：刷新并返回批次（待定区间、采用依据、已发布项），用于保存重开或源再次修订后续审。
  - `op: "decide"`（`batch_id, action_id, resolutions`）：记录一个动作内逐区间的 `source`/`keep`/`pending` 决定到其批次草稿，不发布。
  - `op: "submit"`（`batch_id`）：只发布决定完整的动作，待定项保留在批次中。
  - `op: "cancel-item"`（`batch_id, action_id`）：取消该动作未发布的批次决定，不影响其他批次已发布结果。
