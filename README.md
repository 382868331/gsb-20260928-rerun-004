# 角色动画制作台

React 负责编辑、画布和播放；Python 负责动画计算、工程校验、JSON 存储与动作导出。

## 功能

- 内置简单人形骨架，通过父子层级做前向运动学求值。
- 任意时间拖动预览，姿态按时间线性插值，角度使用 ±180° 最短路径跨越 0°/360°。
- 关键姿态支持跳转、移动时间、复制和撤销。
- 支持动作分层：每层拥有独立关键帧、作用骨骼、权重、时间范围与淡入淡出；层在局部姿态空间按权重覆盖所选骨骼后再做父子旋转求值，未选父骨骼含义保持明确（层只改所选骨骼的局部变换，子骨骼继续随父级世界旋转累积）。
- 层关键帧可单独选择、移动和编辑；时间窗边界配合淡入淡出保证叠加/切换动作不跳姿，保存重开后逐帧预览与导出共用同一求值结果。
- 支持把多层动作按时间范围 + 骨骼范围「整理」成可继续编辑的新动作：按 60fps 逐帧烘焙合成姿态（含平滑权重过渡，逐帧精确固化），整理片段播放与原工程一致，范围以外内容和源分层工程均不改动；整理前会报告缺失骨骼和部分覆盖的不兼容层，任一问题都直接放弃，不会提交半份结果；整理后在原动作与新动作之间逐帧核对姿态，失败时完整保留分层工程。
- 动作层支持权重关键帧，可在淡入淡出过程中任意时刻平滑过渡，并支持过渡中途正/反向反复调整；带权重关键帧的层可直接整理。
- 整理后的局部返修：源工程修改后，自动列出旧整理动作中受影响的时间区间与骨骼，由用户勾选要更新的区间；含人工返修关键帧的区间单独提示，可保留手工结果或重新采用源动作，不会静默覆盖；相邻返修区间保持姿态连续，每次应用是独立一步，撤销一处决定不影响其他已确认区间。
- 整理动作带修订号（revision）与历史版本快照：保存重开后仍能区分源修订、整理结果与人工返修（关键帧 origin 标记），旧版本可在动作面板单独回放。
 - 同一段源动作可被多个整理动作引用：源工程修改后按动作分别列出受影响的时间区间、骨骼与采用依据，每个动作独立勾选决定，不会因为源相同而强制同步。
 - 一次源修订的采用决定可保存为多个可对比方案：方案可分别保留手工修正或采用完整新源动作；保留的手工关键帧以 kept_source_version 明确依附的源版本，源再次修改时会重新识别冲突。
 - 每次采用/保留决定写入采用记录（decision_log）：两次修订影响相交的时间与骨骼时，撤回较早决定前会列出依赖它的较晚决定（一并撤回）与仍可独立保留的较晚返修（按原样重放保留），不会直接抹掉无关返修。
 - 方案对比逐帧区分差异来源（源变化采用 / 人工保留），并对每个采用区间的边界做区间内外姿态连续性核对；发布某个方案只生成该方案的整理版本，其余方案继续可编辑，旧发布版本仍可回放；共享关系、冲突决定与独立撤回范围随工程保存，关闭重开后不变。
- 源工程（`version`）与每个整理动作（`source` 溯源：来源动作 id、源版本、时间/骨骼范围、fps、生成时间）分开保存；撤销整理、修改底层关键帧后重新整理、保存重开都能区分源动作与新动作的版本。
- 播放支持重复循环与单次播放。
- 保存前检查缺失父骨骼、重复根节点、自引用、层级循环、缺失骨骼姿态和时间越界等冲突。
- Python 工程原子写入 `backend/data/project.json`。
- 导出按固定 FPS 生成每帧的局部姿态和世界姿态，前端保存时会与 Python 导出结果比对。

## 启动

```bash
cd backend
python server.py --reset --port 8000
```

```bash
cd frontend
npm install
npm run dev
```

打开 Vite 输出的本地地址（默认 `http://127.0.0.1:5173`）。Vite 已把 `/api` 代理到 Python 服务。

## 测试与构建

```bash
cd backend
python -m unittest discover -s tests -v
python -m py_compile server.py animation_core.py

cd ../frontend
npm test
npm run build
```

## HTTP API

- `GET /api/project`：读取工程，不存在时初始化内置角色。
- `POST /api/project`：校验并保存工程。
- `GET /api/evaluate?time=0.63`：获取指定时刻的局部姿态和世界姿态。
- `GET /api/export?fps=24`：导出逐帧动作数据。
- `POST /api/bake`：按 `{project, range_start, range_end, bones, name}` 原子整理新动作；存在缺失骨骼或不兼容内容时返回错误且不修改工程。
- `POST /api/rebake`：按 `{project, action_id}` 返回受影响区间分析；附带 `decisions`（每区间 `source`/`keep`）时应用局部返修并返回带新修订号与历史快照的动作。
 - `POST /api/rebake/all`：按 `{project}` 返回所有共享源动作的受影响区间总览（各动作独立）。
 - `POST /api/rebake/withdraw`：按 `{project, action_id, decision_id}` 预览撤回影响（依赖项与可独立保留项）；附带 `apply: true` 时执行撤回。
 - `POST /api/plans`：按 `{project, action_id, name, decisions}` 保存一个可对比的返修方案（不修改动作）。
 - `POST /api/plans/compare`：按 `{project, action_id, plan_ids?}` 对比当前修订、历史版本与各方案，逐帧标注差异来源并核对边界连续性。
 - `POST /api/plans/publish` / `POST /api/plans/delete`：按 `{project, action_id, plan_id}` 发布或删除方案；发布只生成该方案的整理版本。
